# R2 measured-meter forecasting audit

This folder addresses Reviewer 3, points 2 and 3. It preserves the exact R1
architecture, inputs, normalization and selected buildings, adds full-training-
pool learning curves and validation-only checkpoint selection, and reports
paired building differences with synchronized calendar-block uncertainty.
The work concerns temporal forecasting after retraining on the same buildings.
It does not demonstrate unseen-site transfer or physical BAS control.

`PROTOCOL.json` and `PROTOCOL.sha256` were frozen before additional training or
2017 scoring. The 2017 results were already reported in R1; this is an explicitly
identified reused-holdout robustness audit. `DECISIONS_LOCK.json` fixes budgets,
checkpoint epochs and hashes before test scoring. No new test score determines
a checkpoint, training extension, model, seed, data cleaning or meter selection.

## Reproduce without overwriting the supplied results

Install the versions recorded in `ENVIRONMENT.json`. CPU PyTorch is available
from the official PyTorch CPU wheel index. The experiment uses Python 3.12.14,
PyTorch 2.10.0+cpu, NumPy 2.3.5, pandas 2.2.3, scikit-learn 1.8.0,
SciPy 1.17.0 and Matplotlib 3.10.8.

From the submission-package root, with the R1 research directory available:

```bash
python r2_experiments/measured/reproduce.py \
  --source-research research \
  --output-root reproduction/measured
```

Alternatively, point `--source-research` to
`sources/r1_package/JER_S105_Revision_20261012/research` when the package preserves
that original extraction structure. The required source directory contains
`revision/external/raw/`, original checkpoints/predictions, and the frozen
BDG2 subset. Set `JER_R1_RESEARCH` when running the individual scripts elsewhere.

The reproduction command creates a new directory, copies the frozen code and
source lock, verifies official input hashes, prepares exact row bindings, records
new hardware, trains, locks validation choices, scores, computes uncertainty and
verifies the outputs. It refuses to overwrite an existing nonempty output
directory. If fitting is interrupted, rerun `train_budget.py` inside the new
directory to resume saved optimizer and RNG states. Scoring remains gated behind
the validation decision lock. The supplied source archive is not modified.

## Scientific design

- Original seeds 11, 23 and 37; all four original neural architectures; fixed
  hyperparameters and 13 measured-input features.
- All 84,928 eligible Jan–Oct 2016 training sequences; complete Nov–Dec 2016
  validation (17,296 windows); the original 98,483 common observed 2017 targets.
- Initial ten epochs, with predeclared all-model extensions to 20 and at most
  40 using validation curves only. Every epoch has 332 minibatch updates.
- Architecture-level checkpoint choice minimizes the mean validation RMSE of
  the three seeds; all three seeds use the selected epoch and none is dropped.
- Fixed 6,800-window training diagnostics and complete validation diagnostics
  each epoch. Equal-update landmarks are supplementary validation controls,
  not claims of equal computation or isolated sample-size effects.
- Exploratory paired 14-day calendar-block intervals (5,000 replicates), with
  predeclared 7- and 28-day sensitivities; blocks remain inside calendar quarters
  and draws are synchronized across buildings, seeds and comparators.
- Site/time perturbations resample six site clusters, retaining both buildings
  per selected site. They do not establish population-wide site generalization.
- Seed SD remains a separate training-variability measure. No hourly IID tests,
  economic-value claim, confirmatory ranking or equivalence test is introduced.

The 24-row input tensor contains lagged features extending the effective raw
meter history to 48 hours. Past observations can cross a chronological split
boundary, as required for causal online forecasting; target labels are assigned
by target timestamp. Calendar blocks preserve this dependence more appropriately
than treating overlapping hourly windows as independent observations.

## Outputs and storage

`FACTS.json` and `REPORT.md` contain exact final facts and relative output paths.
`results/` contains all seed metrics, paired building results, calendar-block
draws and intervals, row-level predictions, coverage exclusions and verification.
`states/` contains epoch weight files and resumable optimizer/RNG checkpoints.
`cache/` contains exact intermediate input tensors and selected source subsets;
these caches can be regenerated by `prepare_data.py` and are not new observations.

The original five-epoch, 6,800-window results remain in a separate legacy table.
They are not silently replaced by the validation-selected full-pool comparison.
The upstream BDG2 data retain the unmodified source license in
`source/BDG2_LICENSE.txt`, separate from the synthetic-data license. No meter
target is imputed, and published zeros and unusual readings are retained.
